## Обязательный вход в новый чат

- Перед началом реальной работы агент обязан восстановить текущее состояние мобильного контура, а не опираться на память.
- Для `GOSHA_MOBILE` это обязательно включает:
  - чтение `START_HERE_FOR_NEW_CHAT.md`;
  - чтение `docs/NEW_CHAT_CHECKPOINT_RU.md`, `docs/AGENT_CHECKPOINT_RU.md`, `docs/PROJECT_STATUS_RU.md`;
  - если задача iOS-first, проверку, не вынесена ли она уже в отдельный репозиторий `GOSHA_MOBILE_IOS`;
  - проверку `git status --short --branch`;
  - проверку верхнего коммита через `git log --oneline -1`;
  - если задача относится к общему контуру `Гоша`, проверку свежей контрольной точки на рабочем столе.
- В первом содержательном ответе нового чата агент обязан явно сообщить:
  - текущую ветку;
  - текущую стадию Android-контура;
  - главный следующий шаг;
  - что относится к Android, а что уже вынесено в отдельный iOS-репозиторий.

## Что это за проект

- `GOSHA_MOBILE` — отдельный Android-клиент платформы `Гоша`.
- Этот репозиторий теперь считается Android-first контуром.
- Это самостоятельный проект, созданный одноразовым копированием из старого Android-клиента `AI_ROBOT`.
- После копирования это уже независимый контур.
- Для iOS теперь создан отдельный репозиторий:
  - `https://github.com/MaxCorpOrg/GOSHA_MOBILE_IOS`
- Старое опубликованное приложение из `AI_ROBOT` считается легаси-контуром и не является основным объектом этой папки.
- Если нужно быстро понять, где сервер, голоса, прошивка и мобильный контракт, сначала смотри:
  - `/home/max/GOSHA_PLATFORM/docs/GOSHA_PROJECT_MAP_RU.md`

## Главные правила

- Проектировать мобильный клиент как отдельный масштабируемый контур платформы `Гоша`.
- Не возвращать жёсткую зависимость от `AI_ROBOT`.
- Не полагаться на старые адреса `8876/8890` как на рабочие адреса по умолчанию.
- Пользовательский бренд приложения — `Гоша`.
- В переходный период клиент должен принимать оба префикса сети робота:
  - `GOSHA-`
  - `Xiaozhi-`
- Старый опубликованный пакет `com.maxcorp.edgeconnector` не менять.
- Новый проект использует собственный идентификатор:
  - `com.maxcorp.gosha.mobile`

## Правила веток и `git worktree`

- Для параллельных направлений используй отдельные рабочие деревья `git worktree`, а не одну общую рабочую копию Android-проекта.
- Канонический путь ручных рабочих деревьев разработчика:
  - `/home/max/worktrees/gosha/<контур>-<задача>`
- Для новых ручных задач в `GOSHA_MOBILE` базой по умолчанию считай `main`.
- Для ручных рабочих веток используй такие префиксы:
  - `feature/` — продуктовая функция
  - `hotfix/` — срочное исправление
  - `release/` — подготовка публикации и магазина приложений
- Не смешивай в одной ветке разные мобильные направления без явной причины:
  - локальный портал и flow подключения
  - runtime-диагностика
  - публикационный контур `RuStore`
  - серверный пакет подключения
- `iOS` не считается веткой этого репозитория:
  - если начнётся отдельный клиент `iOS`, для него нужен отдельный репозиторий, а не ветка внутри `GOSHA_MOBILE`.
- Перед созданием нового `worktree` либо закоммить текущие изменения, либо перенеси их в отдельную ветку, чтобы не смешивать продуктовую логику с публикационными пакетами.

## Правила общения с оператором

- Пиши отчёты, планы, пояснения и контрольные точки нормальным русским техническим языком.
- Не используй англо-русский суржик в обычном тексте.
- Английский оставляй только для команд, путей, названий файлов, функций, переменных, веток, коммитов и кода.
- Если технический термин нельзя убрать, сразу поясняй его по-русски.
- Пиши так, чтобы руководитель проекта, оператор и разработчик одинаково понимали смысл без дополнительных расшифровок.
- Для типовых слов используй такие формы:
  - `verified online` — подтверждённо в сети
  - `detect` — обнаружение
  - `handshake` — проверочный обмен запрос-ответ
  - `scope` — область изменений
  - `branch` — ветка
  - `commit` — коммит
  - `push` — отправка изменений
  - `pull` — получение изменений
