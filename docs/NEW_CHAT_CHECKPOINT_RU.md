## Где остановились

- В `GOSHA_MOBILE` уже унифицированы правила общения агента:
  - корневой и локальные `AGENTS.md` требуют понятный русский технический язык;
  - для типовых терминов закреплены русские формы и пояснения.
- Для локального портала поднято отдельное рабочее дерево:
  - `/home/max/worktrees/gosha/mobile-portal`
- Текущая рабочая ветка этого контура:
  - `feature/mobile-hotspot-portal`
- В этой ветке уже сделана рабочая правка пользовательского пути локального портала:
  - `MainActivity.startRobotWifiPortal()` снова открывает встроенный экран `HotspotPortalActivity`, а не внешний браузер;
  - сам экран загружает портал робота через `RobotPortalClient` и использует найденный `Network` робота;
  - дополнительные диагностические сообщения `HotspotPortal` и `GoshaRobotWifi` оставлены на месте.
- Тем же днём поверх рабочего портала добавлена новая стабилизация Android-контура:
  - в локальном состоянии появился флаг `setupCompleted`;
  - после успешного возврата в `MENU` приложение больше не должно само открывать шаг переподключения только потому, что рядом ещё видна сеть робота или панель ответила с задержкой;
  - добавлен тихий фоновый контур проверки `Wi‑Fi` / панели / локального адреса без смены экрана;
  - мобильный клиент теперь сам отправляет в панель `mobile_presence` со состояниями `phone_on_robot_wifi`, `robot_hotspot_visible`, `home_wifi_local`, `not_found`;
  - `ConnectorForegroundService` теперь зарегистрирован в `AndroidManifest`, оформлен под Android 14 и должен стартовать автоматически при наличии реального `robotHost`.
- Поверх этой стабилизации следующая локальная серия `2026-05-27` уже добивает скорость и прозрачность:
  - `MENU` теперь должен сразу показывать, что приложение проверяет робота, не видит домашний `Wi‑Fi`, видит рядом сеть робота или уже нашло локальный адрес;
  - шаг повторного подключения `Wi‑Fi` теперь сам уточняет текущее состояние робота, не дожидаясь ручного запуска;
  - локальный поиск сначала проверяет сохранённый `robotHost`;
